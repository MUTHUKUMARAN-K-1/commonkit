03 / REPRODUCE THE CHECKS

Same checks.
Your terminal.

From the CommonKit repository, with Node.js 24. Built-in Node APIs only: no wallet, keys or dependency installation needed.

The default command checks both flows. Add a flow option to inspect just one.

# Both recorded flows
npm run verify:testnet

# Selected flow
npm run verify:testnet -- --flow normal

# Machine-readable report for both flows
npm run --silent verify:testnet -- --json

Exit 0: all checks pass · 1: mismatch · 2: incomplete/unavailable.

04 / KEEP THE EVIDENCE IN CONTEXT

Recorded checkpoints.

Saved during the rehearsal, not fresh RPC results. Use these to understand the intermediate balances.

    What the evidence proves and its limits

    Checks rely on public RPC responses, not independently verified light-client proofs. The code hash pins the recorded deployment; it is not a reproducible-build attestation or a security audit.

    Both council accounts are controlled by the demo operator. Two distinct account approvals do not establish independent human governance. Synthetic evidence hashes bind files to calls but cannot prove physical custody or damage.

    Normal return is accepted by the custodian. Two council votes authorize the DAO fee withdrawal; the first vote must not execute that withdrawal.

    Withdrawals consume account credits. Receipts prove the recorded transfers, not a general per-booking withdrawal mechanism. Read the shared verification source ↗
